# Optimal Inflow Control for Transport Equations with Uncertain Velocities and Demand

MATLAB code accompanying:

> S. Göttlich, T. Schillinger. *Optimal Inflow Control for Transport Equations with
> Uncertain Velocities and Demand*. 

This README explains how to run the code, which script produces which figure in the
paper, which parameters you can change, and what the current limitations are.

## Requirements

- MATLAB (developed/tested on R2025a; no version-specific language features are used
  beyond ordinary functions and scripts, so recent releases should work).
- **Statistics and Machine Learning Toolbox** — required by both entry scripts
  (`betarnd`, `betapdf`, `quantile`).
- **Optimization Toolbox** — required by `skriptNonLocal.m` (`fmincon`).
- **Parallel Computing Toolbox** — used by `stochasticNonlocalModel_control_stochastic.m`
  (`parfor` over Monte Carlo realizations). Recommended for reasonable runtime; if
  unavailable, MATLAB may still execute the loop, just serially and slower.

No installation beyond having these two files' folder on the MATLAB path is needed —
just `cd` into the project directory (or add it via `addpath`) and run.

## Repository layout

Two independent entry-point scripts, each with its own set of helper functions:

```
main_v2_26_05_27.m          entry point — Figures 2-6 (linear transport model)
├── sampleSingleSpeedMC.m       sample demand + velocity, simulate, compute L1/L2/L3 error
├── computeOptimalU.m           optimal inflow control (Theorem 3.1 / Prop. 3.3)
├── jacobiMeanClosed.m          closed-form mean demand m(t)              (shared)
├── simulateJacobiTimeDep.m     Monte Carlo simulation of the demand process
├── transportUpwind.m           forward transport solve, grid-based upwind scheme
└── transportUpwind_trajec.m    forward transport solve via characteristics (exact)

skriptNonLocal.m             entry point — Figure 7 (nonlocal extension)
├── stochasticNonlocalModel.m             forward simulation, 1 velocity realization
├── stochasticNonlocalModel_control.m     forward simulation for use as an fmincon objective
├── stochasticNonlocalModel_control_stochastic.m  stochastic objective (MC average, parfor)
├── stochasticNonlocalModel_forward.m     forward simulation for several realizations at once
├── computeNonlocalKernelWeights.m        precomputed nonlocal-kernel quadrature weights
└── jacobiMeanClosed.m                    closed-form mean demand m(t)   (shared)
```

Both scripts are organized into MATLAB code sections (`%%`), each independently
runnable via *Run Section* (Ctrl+Enter) once the earlier sections in the same file
have run at least once — later sections reuse parameters (`theta_fun`, `d0`, `kappa`,
`sigma`, `dt`, `alpha`, `beta`, ...) set by earlier ones rather than redefining them.

## How to run

1. Open `main_v2_26_05_27.m` in MATLAB and run its three sections **in order**
   (top to bottom): *Figure 2 & 3*, *Figure 4 & 5*, *Figure 6*.
2. Open `skriptNonLocal.m` and run it top to bottom (its two halves produce the left
   and right panel of Figure 7, respectively, and also depend on each other's setup).
3. Figures pop up as the script progresses; there is no separate "export" step.

**Expect noticeable runtimes at full paper-fidelity parameters.**
You may also test the codes with smaller values of MC, or smaller potential choices of the
length of the piecewise constant intervals or the variances

**Velocity distribution restricted to the shifted/stretched Beta family.**
Note that the code is currently written to allow shifted and scaled beta distributions for the 
uncertain velocity only. A distribution outside the Beta family (e.g. truncated normal, 
empirical/data-driven) would need `varphi` in `computeOptimalU.m` — and the sampler in
  `sampleSingleSpeedMC.m` — changed together (they must stay consistent with each
  other; see the design note in `computeOptimalU.m`'s header).
  `alpha=beta=1` gives the uniform case used throughout the paper's experiments; other
  `alpha,beta` give a genuine (if constrained) family of skewed bounded distributions.
  
Results are **not exactly reproducible** run-to-run: nothing in the code seeds
MATLAB's random number generator.

## Configuration

### `main_v2_26_05_27.m`

Each of the three sections starts with its own parameter block; the same names mean
the same thing in all three.

| Variable | Meaning | Current value(s) |
|---|---|---|
| `T` | Time horizon | 16 (Fig. 2-5), 6 (Fig. 6) |
| `MCruns` | Number of Monte Carlo realizations of demand + velocity | 25 000 everywhere (matches the paper's Sec. 6.1) |
| `alpha`, `beta` | Shape parameters of the velocity distribution — see [Velocity distribution](#velocity-distribution) below | 1, 1 (→ uniform) |
| `lambdaMIN`, `lambdaMAX` | Support of the velocity distribution | `[1,3]` (Fig. 2/3/6); swept around 2 in Fig. 4/5 (see `shifts`) |
| `theta_fun`, `d0`, `kappa`, `sigma` | Demand process: mean-reversion target function, initial value, mean-reversion speed, diffusion coefficient — see [Demand process](#demand-process) | `4*(0.5+0.25*sin(pi*t))`, `1.6`, `4`, `0.15` |
| `dt` | Fine time-discretization step for the forward simulation | `0.0005` |
| `dtU` | Control-grid cell width `|Pi_n|` for the *Figure 2 & 3* / *Figure 6* sweeps | `2.^(1:-1:-4)` |
| `shifts` | Exponents `k` for `Var(lambda) ∝ 2^k` in the *Figure 4 & 5* sweep | `3:-1:-6` |
| `randeinzug` | Half-width of the interior evaluation window `J=[randeinzug, T-randeinzug]`, excluding boundary effects from the objective | 2 (Fig. 2-5), 0 (Fig. 6) |

arguments (all default to the values above): `outputMode` ('piecewise'/'continuous'),

the control under a different assumed velocity range than the one actually simulated
— used for the "proxy" and deterministic-reference curves), and `lambdaIn`/`Xin` (reuse
existing realizations instead of resampling, for a paired comparison). See the
function's header comment for details.

### Velocity distribution

`lambda` is sampled as a **shifted and stretched Beta(alpha, beta) distribution** on
`[lambdaMIN, lambdaMAX]`: `lambda = lambdaMIN + (lambdaMAX-lambdaMIN) * Y`,
`Y ~ Beta(alpha,beta)`. `alpha=beta=1` recovers the uniform distribution
(`Beta(1,1) = U(0,1)`) used throughout the current experiments. `computeOptimalU.m`'s
control computation uses exactly this density (`betapdf(...)/(\lambdaMAX-\lambdaMIN)`),
so the sampled realizations and the control computed for them are always consistent —
change `alpha`/`beta` in `main_v2_26_05_27.m` and both pick it up automatically.

### Demand process

The demand `D(t)` is simulated as a Jacobi-type mean-reverting SDE,
`dX = kappa*(theta(t)-X)dt + sigma*sqrt((X-a)(b-X)) dW`, with the state bounded to
`[a,b]` (hardcoded to `a=0, b=4` inside `simulateJacobiTimeDep.m` — see
[Limitations](#limitations)). Its expectation `m(t)` has a semi-closed form evaluated
numerically in `jacobiMeanClosed.m`, which any of the parameters `theta_fun` (a
function handle), `d0`, `kappa` feed into directly.

## Comment on a interesting performance issue

`jacobiMeanClosed.m` computes the mean demand `m(t) = e^{-kappa t} d0 + kappa *
int_0^t e^{-kappa(t-s)} theta(s) ds`. This calculation is costly when implemented in 
a classical way. Therefore, we did the following: It caches a cumulative-integral 
table `G(t) = int_0^t e^{kappa s} theta(s) ds` (computed once via `cumtrapz` on a 
fine grid) and evaluates any query by interpolating into that table instead of 
re-integrating. The cache is a `persistent` variable inside the function itself, keyed 
on `(kappa, d0, theta_fun)` and automatically rebuilt whenever those change or a query 
falls outside the currently cached range — so **no call site anywhere in the repository 
needed to change**. Eachparallel worker (`parfor`) keeps its own independent cache.

## Limitations

- **Velocity distribution restricted to the shifted/stretched Beta family.**
  as already described above
- **`alpha<1` or `beta<1` can be numerically fragile.** The Beta density is unbounded
  at the corresponding edge of `[lambdaMIN,lambdaMAX]`, and the quadrature grid `dl` in
  `computeOptimalU.m` includes the exact edges — such shape parameters may produce
  `Inf`/`NaN` without a strictly-interior quadrature grid (not currently implemented).
- **The nonlocal model (`skriptNonLocal.m`, Figure 7) is a separate, simpler
  uncertainty model**, not connected to the Beta-distribution generalization above: it
  uses an additive perturbation `epsilon ~ U([-tau,tau])` on the velocity function
  `v(rho)`, always uniform. Extending it to a non-uniform perturbation would require
  separate changes there.
- **Demand process fixed to one SDE family.** Swapping to a different demand-process
  model would need both a new sampler (replacing `simulateJacobiTimeDep.m`) and a new
  closed-form/quadrature mean function (replacing `jacobiMeanClosed.m`). The state
  bounds `a=0,b=4` are hardcoded inside `simulateJacobiTimeDep.m`, not exposed as
  parameters.
- **Spatial domain fixed to `[0,1]`** throughout `transportUpwind*.m` and
  `stochasticNonlocalModel*.m` — not parameterized.
